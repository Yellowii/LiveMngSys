# LiveMngSys 需求与模块边界

> 目标：将抖音直播数据、主播工具、点歌和直播展示整合为一个可扩展的局域网服务。
> 本文件描述业务目标和模块边界；具体接口、数据表和实现方案分别记录在 `Docs/`。

## 0. 总体原则

- 以“直播间”和“直播场次”为核心上下文。所有实时事件、快照、复盘数据都必须能追溯到场次。
- 采集、存储、业务规则、展示和外部推送分层，模块之间通过稳定的内部事件/API/快照通信。
- 先保持现有功能和数据兼容，再进行小步重构；每个模块独立测试、独立提交、可回滚。
- 运行态数据、登录态、Cookie、浏览器 profile、媒体缓存和本机配置不进入代码仓库。
- 实时流按时间追加；榜单、队列和优先级任务保持各自的业务排序。

## 1. 平台基础层（横向能力）

### 1.1 统一服务网关

- 统一启动和停止 `WebServer`、`MusicBot`、`DouyinListener`。
- 统一配置服务地址、端口、健康检查、服务状态和系统指标。
- 对外只暴露主网关；内部服务默认使用回环地址。

### 1.2 事件总线、推送与接口契约

- 将采集到的标准化事件分发给点歌、上车、UI、复盘和外部程序。
- 支持 WebSocket/HTTP 推送；未来可扩展公网通知和小智 MCP 广播。
- 明确事件版本、幂等键、时间戳、场次 ID 和错误处理，不让业务模块直接依赖底层协议对象。

### 1.3 配置、权限与运行状态

- 区分公开默认配置、用户运行配置和账户登录态。
- 为敏感配置提供示例文件和校验；不得在日志、接口或前端回显凭据。
- 记录服务启动、异常、重连和配置变更状态。

## 2. 直播采集层

### 2.1 开播监控

- 支持通过抖音用户 ID、直播间 URL 解析直播间并监控开播状态。
- 支持多个直播间并行监控，处理开播、下播、断线和重连。
- 产出统一的房间状态和场次生命周期事件，供其他模块订阅。

### 2.2 弹幕与直播事件监听

- 按直播间、直播场次接收并解析弹幕、礼物、点赞、关注、进场、会员、粉丝团等事件。
- 保存原始事件和标准化事件；解析失败时保留原始帧，便于协议审计和回放。
- 创建当前场次快照，提供在线观众、榜单、统计和最新事件等查询能力。
- 监听服务不承载 UI 逻辑；登录和浏览器辅助流程与日常直连监听解耦。

## 3. 数据与运营层

### 3.1 粉丝数据库

- 维护用户基础资料、关注关系、粉丝团/勋章、会员、等级和历史互动。
- 以事件增量更新为主，以 HTTP/榜单快照作为补充；明确字段来源和优先级。
- 支持按用户、场次和时间查询，避免重复写入并保留重要状态变化。

### 3.2 直播复盘

- 按场次汇总弹幕、礼物、观众、榜单、点歌和机器人操作。
- 支持时间线检索、关键词/用户筛选、统计摘要和原始事件定位。
- 复盘读取不影响实时监听；大体量原始数据采用归档或分页策略。

### 3.3 礼物与资源资产库

- 管理礼物图标、动画、音效和触发规则，支持本地自定义资源。
- 统一资源 URL、缓存、版本和缺失资源的降级显示。
- 资源库与事件解析解耦，避免资源变更影响历史数据。

## 4. 直播互动业务层

### 4.1 点歌机器人

- 解析弹幕点歌、顶歌、超级置顶、切歌、播放、暂停、查询余额等命令。
- 维护队列、优先级、黑名单、重复歌曲策略和播放状态，并向 UI/外部模块推送变化。
- 当前网易云点歌功能基本可用；后续以适配器方式增加 QQ 音乐、汽水音乐、酷狗等平台。
- 音源校验、试听片段处理、歌词和本地歌曲导入必须保持可测试、可替换。

### 4.2 上车与粉丝互动

- 根据现有规则处理上车、排队、续费会员和相关提示；规则与展示分离。
- 支持查询当前队列、历史记录、用户资格和处理结果。
- 规则文件是业务依据，代码实现需补充异常、重复请求和人工干预策略。

### 4.3 批量续火花与私信自动化

- 支持读取最近会话、筛选目标用户、预演批量任务、确认后发送并记录结果。
- 默认仅预演；实际发送必须二次确认、限速、可中止并可追踪失败项。
- 使用独立聊天登录态，不占用直播监听浏览器 profile。

## 5. 直播展示与主播工具层

### 5.1 实时弹幕工作台

- 提供适合主播快速阅读的自定义界面，突出有效消息并补充抖音原生信息缺失。
- 支持消息筛选、置顶、用户资料/勋章/粉丝团信息、礼物和互动提示。
- 支持按规则进行语音播报；TTS 使用 sherpa-onnx 模型时，模型、音色和队列配置可替换。

### 5.2 直播 UI 与卡片

- 支持直播背景、主题、布局和卡片配置；保留现有 GUIDemo/ReStyle 的独立页面结构。
- 卡片区至少包括：实时消息、点歌/播放、互动状态、榜单和自定义扩展卡片。
- 支持上场榜单分析：榜一、观看时长、上场续费会员、星守护等，并标注统计时间范围。

### 5.3 字幕与翻译

- 音频采集：可选择本机输入设备，并持续以小块音频送入独立的 sherpa-onnx 流式 ASR 进程。
- 实时字幕：说话期间只将可修订的 `partial` 结果用于前端即时预览；VAD/endpoint 检测到句尾静音后提交 `final` 完整句子，前端保留已完成句子的历史记录。
- 文本清洗：Python 业务层仅处理 `final`，以纯规则过滤语气词、丢弃 1-2 字无效片段，并归一化空格与换行。ASR 错字不假定由翻译模型自动纠正。
- 翻译字幕：`partial` 严禁进入翻译；仅清洗后的 `final` 通过 HTTP 送入独立 llama.cpp server。翻译器只执行中外翻译，不负责纠错或润色，目标语言可配置。
- 进程隔离：sherpa-onnx ASR、Python 字幕管线和 llama.cpp 翻译服务独立运行。翻译服务不可用时仍须输出源语言 ASR 字幕，任一推理进程退出不得连带终止另一进程。
- TTS 播报属于可选输出，不参与实时字幕的 ASR 到翻译链路。
- 字幕链路应与直播事件链路解耦，支持关闭、低延迟更新、错误降级和历史回放，并通过 HTTP/WebSocket 接口对外提供状态。

## 6. 外部扩展层

- 提供稳定的 HTTP/WebSocket API、事件订阅和场次快照，供其他本地程序调用。
- 后续可增加公网通知、MCP、OBS/虚拟声卡、其他音乐平台和第三方数据源适配器。
- 外部集成必须采用适配器/插件边界，不能把第三方 SDK 直接渗透到核心领域模型。

## 7. 优先级与验收顺序

### P0：先稳定基线

- 统一网关、开播监控、弹幕监听、场次快照、事件推送和敏感配置边界。
- 验收：可启动/停止，多房间可重连，事件可按场次查询，核心服务健康状态可见。

### P1：完成核心运营闭环

- 粉丝数据库、点歌、上车规则、实时弹幕工作台、基础直播卡片。
- 验收：真实事件与测试事件均可驱动业务；队列、用户状态和 UI 状态一致；关键规则有自动化测试。

### P2：增强内容生产与复盘

- 字幕、翻译、礼物特效库、直播复盘、批量续火花。
- 验收：任务可预演/取消/重试，复盘可按场次检索，资源缺失和模型不可用时可降级。

### P3：平台扩展

- 其他音乐平台、公网通知、小智 MCP、OBS 和更多第三方适配器。
- 验收：新增平台不修改核心队列、事件模型和现有 UI；适配器可独立测试和禁用。

## 8. 当前实现映射

- `DouyinListener`：直播采集、协议解析、场次快照、用户/粉丝数据和私信辅助能力。
- `WebServer`：统一网关、代理、健康检查、系统指标和公共 API。
- `MusicBot`：点歌队列、播放器、网易云 API 适配和点歌 UI。
- `GUIDemo`：直播展示、实时弹幕、卡片和字幕相关前端原型。
- `ReStyle`：可复用的主题与组件设计工具，不直接承担直播业务状态。
- `Docs/Rules`、`Docs/Database`、`Docs/memory`：规则、数据字典和项目决策记录。

## 9. 重构约束

- 先建立并保留 baseline；每次只改变一个明确模块，提交信息说明迁移范围和验证结果。
- 优先抽取领域模型、事件契约、存储接口和配置边界，再调整目录结构。
- 不以“大规模重写”替代兼容迁移；未验证的协议、模型和外部服务不得作为已完成能力宣传。
