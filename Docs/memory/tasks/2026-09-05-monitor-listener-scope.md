# 2026-09-05 开播监控与弹幕监听范围约束

状态：进行中；本轮仅处理直播监控、弹幕监听、用户身份解析及对外状态接口。

设计决定：神秘人和匿名用户都允许通过 UID/secUid/displayId、展示文本或数据库缓存恢复真实资料；恢复资料不能清除隐私标签。标准用户字段为 `isAnonymous`、`isMystery`、`privacyLabel`，前端可据此渲染“匿”或“神秘人”角标。

已完成：EventStore 归一化、会话 memory 标签保留、多房间状态监控测试。

范围澄清：多房间仅用于开播状态监控；状态监控不得创建 WSS/浏览器弹幕监听器，也不得写入弹幕场次事件。

场次边界已明确：`web_rid`/`roomId` 是稳定直播间标识；平台 `live_id`/`sessionId` 是每次开播变化的场次标识。弹幕监听仍按单直播间、单场次运行，保存到 `data/sessions/<room-label>/场次<session-id>/`，包含 `session.json`、`parsed.jsonl` 及可选 Raw Proto。

待完成：把仅状态用途的多房间注册表接入服务 API；为单房间弹幕监听保留标准事件、场次快照和健康检查等对外接口。多房间状态监控与弹幕监听生命周期保持分离。
